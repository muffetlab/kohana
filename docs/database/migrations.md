# Migrations

Migrations are version control for your database schema. Each migration is a file that changes the schema (`up()`) and can undo the change (`down()`). Kohana records which migrations ran in a `migrations` table, so every developer and server applies the same changes in the same order.

The commands come with the [console](../minion/index); the database module must be enabled.

## Creating a migration

    php kohana make:migration create_posts_table
    php kohana make:migration add_slug_to_posts_table
    php kohana make:migration change_posts --table=posts

The file goes into `app/migrations`, prefixed with the date and time (`2026_11_21_120000_create_posts_table.php`); migrations run in file name order. `create_*_table` names produce a `Schema::create()` stub, and `*_to_*_table`, `*_from_*_table` names a `Schema::table()` stub.

A migration file returns an anonymous class:

    <?php

    use Kohana\Database\Migrations\Migration;
    use Kohana\Database\Schema\Blueprint;
    use Kohana\Database\Schema\Schema;

    return new class extends Migration
    {
        public function up(): void
        {
            Schema::create('posts', function (Blueprint $table) {
                $table->id();
                $table->foreignId('user_id')->constrained()->cascadeOnDelete();
                $table->string('title');
                $table->text('body')->nullable();
                $table->boolean('published')->default(false);
                $table->timestamps();

                $table->index(['user_id', 'published']);
            });
        }

        public function down(): void
        {
            Schema::dropIfExists('posts');
        }
    };

Modules can ship migrations too: files in an enabled module's `migrations/` directory run with the application's.

## Running migrations

    php kohana migrate                        # run pending migrations as one batch
    php kohana migrate --seed                 # then run DatabaseSeeder
    php kohana migrate:status                 # what ran, in which batch
    php kohana migrate:rollback               # revert the last batch
    php kohana migrate:rollback --step=2      # revert the last two migrations
    php kohana migrate:rollback --all         # revert everything

Every command accepts `--database=group` to use another connection from `config/database.php`. A migration can also pin itself to a group with `protected ?string $connection = 'reporting';`.

On PostgreSQL each migration runs in a transaction, so a failing migration leaves nothing half done. MySQL commits schema changes immediately; keep MySQL migrations small.

[!!] In production (`APP_ENV=production`), `migrate`, `migrate:rollback` and `db:seed` only run with `--force`.

## Schema builder

`Schema` works on the default connection (or the migration's), `Schema::connection('group')` on another one. It supports MySQL/MariaDB (MySQLi or PDO) and PostgreSQL.

| Method | Does |
|---|---|
| `Schema::create('posts', fn (Blueprint $table) => ...)` | Creates a table |
| `Schema::table('posts', fn (Blueprint $table) => ...)` | Changes a table |
| `Schema::drop('posts')`, `Schema::dropIfExists('posts')` | Drops a table |
| `Schema::rename('posts', 'articles')` | Renames a table |
| `Schema::hasTable('posts')`, `Schema::hasColumn('posts', 'title')` | Checks the schema |
| `Schema::toSql('posts', fn (Blueprint $table) => ...)` | Returns the SQL without running it |

### Column types

| Method | MySQL | PostgreSQL |
|---|---|---|
| `id()`, `bigIncrements('id')` | `BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `increments('id')` | `INT UNSIGNED AUTO_INCREMENT PRIMARY KEY` | `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `string('name', 255)`, `char('code', 2)` | `VARCHAR`, `CHAR` | `VARCHAR`, `CHAR` |
| `text('body')`, `longText('body')` | `TEXT`, `LONGTEXT` | `TEXT` |
| `integer()`, `smallInteger()`, `bigInteger()` | `INT`, `SMALLINT`, `BIGINT` | `INTEGER`, `SMALLINT`, `BIGINT` |
| `unsignedInteger()`, `unsignedBigInteger()`, `foreignId()` | `... UNSIGNED` | (no unsigned types) |
| `boolean('active')` | `TINYINT(1)` | `BOOLEAN` |
| `decimal('price', 8, 2)`, `float('ratio')` | `DECIMAL`, `DOUBLE` | `NUMERIC`, `DOUBLE PRECISION` |
| `date()`, `dateTime()`, `time()`, `timestamp()` | `DATE`, `DATETIME`, `TIME`, `TIMESTAMP` | `DATE`, `TIMESTAMP(0)`, `TIME(0)`, `TIMESTAMP(0)` |
| `timestamps()` | nullable `created_at`, `updated_at` | |
| `json('meta')`, `binary('data')`, `uuid('uuid')` | `JSON`, `BLOB`, `CHAR(36)` | `JSON`, `BYTEA`, `UUID` |

### Column modifiers

    $table->string('email')->unique();
    $table->integer('votes')->unsigned()->default(0);
    $table->text('bio')->nullable()->comment('Shown on the profile');
    $table->timestamp('seen_at')->default(DB::expr('CURRENT_TIMESTAMP'));

### Indexes and foreign keys

    $table->unique('email');                         // users_email_unique
    $table->index(['user_id', 'published']);         // posts_user_id_published_index
    $table->primary(['post_id', 'tag_id']);

    $table->foreignId('user_id')->constrained();     // references users.id
    $table->foreign('author_id')->references('id')->on('users')->onDelete('set null');

### Changing tables

    Schema::table('posts', function (Blueprint $table) {
        $table->string('slug')->nullable();          // add columns
        $table->renameColumn('body', 'content');
        $table->dropColumn(['legacy', 'old_flag']);
        $table->dropIndex(['user_id', 'published']); // by columns or by name
        $table->dropUnique('posts_slug_unique');
        $table->dropForeign(['user_id']);
    });

Changing an existing column's type is not supported yet; add a new column, copy the data and drop the old one.
